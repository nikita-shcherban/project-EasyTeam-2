# Clothica — Backend API

Серверна частина інтернет-магазину одягу **Clothica**, створена командою **EasyTeam** як фінальний навчальний проєкт GoIT.

API забезпечує роботу каталогу товарів, облікових записів покупців, замовлень, відгуків і підписок на розсилку. Бекенд зберігає дані в MongoDB, перевіряє вхідні запити та керує доступом до особистих даних користувачів.

## Можливості

- Перегляд каталогу та окремого товару, пошук, фільтрація, сортування й пагінація.
- Отримання категорій товарів.
- Реєстрація та вхід за номером телефону й паролем.
- Сесійна автентифікація через cookies, оновлення сесії та вихід.
- Отримання й редагування власного профілю.
- Оформлення замовлень гостями та авторизованими покупцями.
- Перегляд власних замовлень і зміна їхнього статусу адміністратором.
- Перегляд і створення відгуків з оцінкою товару.
- Збереження email-підписок на розсилку.

## Локальний запуск

### Передумови

- Node.js 22 версії 22.13.0 або новішої в межах гілки 22, або Node.js 24.
- npm.
- Доступна база MongoDB: локальний сервер або MongoDB Atlas.

### 1. Завантажте проєкт і встановіть залежності

```bash
git clone https://github.com/nikita-shcherban/project-EasyTeam-2.git
cd project-EasyTeam-2
npm ci
```

### 2. Налаштуйте середовище

Створіть файл `.env` у корені проєкту. Для локальної MongoDB можна використати:

```dotenv
PORT=3000
MONGO_URL=mongodb://127.0.0.1:27017/database-clothica
NODE_ENV=development
```

Для MongoDB Atlas замініть `MONGO_URL` власним рядком підключення. Надайте користувачу бази доступ до потрібної бази та додайте IP-адресу середовища запуску до списку дозволених адрес Atlas.

| Змінна | Опис |
| --- | --- |
| `PORT` | Порт HTTP-сервера; за замовчуванням `3000` |
| `MONGO_URL` | Рядок підключення до MongoDB |
| `NODE_ENV` | Режим роботи, наприклад `development` або `production` |

Файл `.env` виключений із Git. Облікові дані задавайте у власному середовищі.

### 3. Запустіть сервер

Режим розробки з автоматичним перезапуском:

```bash
npm run dev
```

Звичайний запуск:

```bash
npm start
```

Сервер починає приймати запити після успішного підключення до MongoDB. За стандартних налаштувань базова адреса — `http://localhost:3000`, документація API — [http://localhost:3000/api-docs](http://localhost:3000/api-docs).

### Команди

## Маршрути API

Усі шляхи в таблиці вказані відносно базової адреси сервера.

| Метод | Шлях | Призначення | Доступ |
| --- | --- | --- | --- |
| `POST` | `/api/auth/register` | Реєстрація | Публічний |
| `POST` | `/api/auth/login` | Вхід за телефоном і паролем | Публічний |
| `POST` | `/api/auth/refresh` | Оновлення сесії | Cookies `sessionId`, `refreshToken` |
| `POST` | `/api/auth/logout` | Вихід та очищення cookies | Без обов'язкової автентифікації |
| `GET` | `/api/users/me` | Поточний користувач | Авторизований користувач |
| `PATCH` | `/api/users/me` | Оновлення власного профілю | Авторизований користувач |
| `GET` | `/api/goods` | Каталог товарів | Публічний |
| `GET` | `/api/goods/:goodId` | Товар за ID | Публічний |
| `GET` | `/api/categories` | Категорії товарів | Публічний |
| `GET` | `/api/feedbacks` | Список відгуків | Публічний |
| `POST` | `/api/:goodId/feedbacks` | Створення відгуку | Гість або авторизований користувач |
| `POST` | `/api/orders` | Створення замовлення | Гість або авторизований користувач |
| `GET` | `/api/orders` | Власні замовлення | Авторизований користувач |
| `PATCH` | `/api/orders/:id/status` | Зміна статусу замовлення | Адміністратор |
| `POST` | `/api/subscriptions` | Підписка за email | Публічний |

Для входу, виходу й оновлення сесії також доступні відповідно `/auth/login`, `/auth/logout` та `/auth/refresh`.

### Обліковий запис і сесії

Реєстрація приймає `username`, `phone` і `password`. Приклад тіла запиту:

```json
{
  "username": "Олена",
  "phone": "+380501234567",
  "password": "ExamplePassword123!"
}
```

Для входу передайте `phone` і `password`. Номер телефону має містити `+` та від 8 до 15 цифр, перша цифра — ненульова. Мінімальна довжина пароля при реєстрації — 8 символів.

Після реєстрації або входу сервер встановлює cookies `sessionId`, `accessToken` і `refreshToken`. Access-токен діє 15 хвилин, refresh-токен — 1 добу. Сесії зберігаються в MongoDB. Приватні маршрути перевіряють `sessionId` та `accessToken` і визначають поточного користувача.

Cookies мають параметри `HttpOnly`, `Secure` і `SameSite=None`. Для розгорнутого застосунку використовуйте HTTPS. Браузерний клієнт має надсилати запити з `credentials: 'include'` для Fetch або `withCredentials: true` для Axios; дозволені джерела задаються у `src/utils/allowedOrigins.js`.

Оновлення сесії та вихід не потребують тіла запиту. Успішний refresh повертає `200` з повідомленням `Session refreshed`, logout — `204` без тіла. Пароль не включається до JSON-представлення користувача.

Профіль підтримує зміну полів `username`, `name`, `surname`, `email`, `phone` та `city`.

### Каталог і замовлення

`GET /api/goods` підтримує параметри `page`, `limit`, `category`, `gender`, `size`, `minPrice`, `maxPrice`, `search` та `sort`. Типові значення: сторінка `1`, кількість товарів `12`, сортування `-createdAt`. Максимальний `limit` — `50`. Для сортування доступні `price`, `name`, `createdAt` та їхні варіанти з префіксом `-`.

Приклад запиту:

```http
GET /api/goods?page=1&limit=12&gender=unisex&minPrice=500&maxPrice=2000&sort=price
```

Для створення замовлення передайте `firstName`, `lastName`, `phone`, `city`, `novaPoshtaBranch` та масив `items`. Поле `comment` необов'язкове. Телефон замовника має формат `+380XXXXXXXXX`. Кожна позиція містить `goodId`, `size` та `quantity`; назву й ціну товару сервер отримує з бази та обчислює загальну суму замовлення.

За наявності чинної сесії замовлення пов'язується з користувачем і доступне в його списку замовлень. Статуси замовлення: `pending`, `processing`, `shipped`, `delivered`, `cancelled`. Змінювати статус може користувач із роллю `Administrator`.

## Структура проєкту

```text
src/
├── constants/       # Формати та часові константи
├── controllers/     # Обробка запитів
├── db/              # Підключення до MongoDB
├── middlewares/     # Автентифікація, доступ, логування, помилки
├── models/          # Mongoose-моделі
├── routes/api/      # Маршрути API
├── services/        # Створення сесій і налаштування cookies
├── swagger/         # Налаштування документації API
├── utils/           # Допоміжні налаштування
├── validations/     # Схеми валідації запитів
└── server.js        # Точка входу
```

Запити проходять через маршрут, middleware та контролер, який працює з моделями даних. Обробники невідомих маршрутів і помилок підключені після маршрутів API. Невідомий маршрут повертає `404`, помилки валідації — `400`, помилки доступу — `401` або `403`.

## Розгортання

1. Підключіть репозиторій до сервісу хостингу з підтримкою Node.js або скопіюйте проєкт на сервер.
2. Виберіть сумісну версію Node.js, зазначену в передумовах.
3. Задайте команду встановлення залежностей `npm ci` та команду запуску `npm start`. Окремої компіляції проєкт не потребує.
4. Додайте `MONGO_URL` і `NODE_ENV=production` у змінні середовища хостингу. Використовуйте `PORT`, який надає платформа, або задайте власний порт.
5. Налаштуйте доступ середовища розгортання до MongoDB.
6. Увімкніть HTTPS і задайте дозволені джерела браузерного клієнта у `src/utils/allowedOrigins.js`.
7. Після запуску відкрийте `/api-docs` або виконайте запит `GET /api/goods` за адресою розгорнутого сервера.
